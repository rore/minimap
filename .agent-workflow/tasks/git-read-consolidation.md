## Concrete implementation decisions

1. Identity fast path calls git rev-parse --path-format=absolute --show-toplevel --absolute-git-dir --git-common-dir --verify HEAD once, then reads the same directory identities and HEAD file used today. Validate complete framing and the 40/64-digit commit before constructing any context. Preserve canonical source-key calculation and branch/detached semantics. For legacy Git or genuinely ambiguous path framing, use the existing four-command read rather than inventing values. A normal timeout, non-Git path or missing commit remains unavailable; it must not trigger an overload-amplifying retry loop. Identity remains uncached at source-bound and aggregate final checks. New cancellation/overall deadline/error classification belongs to the later orchestration contract.
2. Candidate buckets use the exact id/filePath tuple and retain insertion order. Search only that bucket using the unchanged feature.sourceIndexes.every(pairwise lineage evidence) predicate. This preserves the current first compatible candidate and prevents a transitive union-find from joining ambiguous components.
3. During source item assembly, map each source index and item ID directly to its matched feature. Appearance assembly uses that lookup rather than scanning all features and versions. A separate set of normal feature keys per group preserves first-appearance order and deduplication. Missing-reference appearances retain their existing handling. Do not alter source objects, public keys, group shape, conflict reads or request-local Git evidence budgets. Bounded lens/filter arrays need no separate abstraction.
4. Keep module scope free of a process-wide evidence cache. Existing merge-base, tree/deletion and transition-history maps remain request-local. A successful result is not enough to make effective Git history immutable: shallow boundaries, replace refs and grafts can change with unchanged HEAD OIDs, and pruning/missing objects can turn previously available evidence into current uncertainty. Disabling replace semantics or adding availability/fingerprint rules would be a material contract choice. Evidence reuse is deferred to a separate reviewed design alongside delivery 2b's scope/freshness/publication policy, not silently claimed complete here.
