# Spec File-Changed Banner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Detect when an external editor (agent or user) modifies the active spec file and surface a sticky, click-to-reload warning banner so the rendered spec body never silently diverges from disk.

**Architecture:** Reuse the existing `#status-banner` element. The server already returns `session.contentHash` on every `getSessionContext`/`getSessionContent` call (computed by `buildTargetMetadata` in `package/minimap/src/sessions.js`). On `loadSpecSession`, stash the hash in `state.spec.lastSeenContentHash`. On each 5 s poll (`refreshSpecReviewState`), compare the new hash to the stash — if different, render a sticky warning banner with a "Reload" button that calls `loadSpecSession(state.spec.selectedPath)`. The banner is rendered through a predicate (`renderSpecFileChangedBanner`) that mirrors the existing `renderWorkspaceWarnings` pattern, and `clearTransientBanner` checks it first so transient toasts ("Comment added.") don't permanently mask it.

**Tech Stack:** Vanilla JS ES modules (no framework), `node --test` for unit tests, Playwright for browser integration tests.

## Behavior Contract

**Hash stash lifecycle:**
- `state.spec.lastSeenContentHash` is `""` until the first successful `loadSpecSession`.
- On `loadSpecSession` success: stamped from `context.session.contentHash || ""`.
- On `loadSpecSession` error or empty selection (`removeSession`): reset to `""`.
- The hash is **never** stamped from `refreshSpecReviewState` — that's the whole point. Only legitimate full-reload paths (initial load, apply, rollback, manual reload) move the watermark forward.

**Detection:**
- After each `refreshSpecReviewState` fetch, compare `context.session.contentHash` (just fetched) against `state.spec.lastSeenContentHash` (the stash).
- If the stash is `""` (first poll before any load completed) → no comparison, no banner.
- If both are non-empty and different → set `state.spec.fileChangedDetected = true` and render the banner.
- If equal → ensure `state.spec.fileChangedDetected = false`, banner is **not** torn down by the poll itself (it would already be cleared by the reload click — the poll only sets the flag, never clears it; clearing happens through reload).

**Banner contents:**
- Tone: `warning` (existing CSS, no new tone needed).
- Text: `This file changed on disk.`
- Trailing inline button: `Reload` (CSS class `status-banner-action`).
- Existing dismiss `×` is still shown — dismissing hides the banner but keeps `fileChangedDetected = true`, so the next poll re-renders it. (This matches the workspace-warning pattern: dismiss is transient, the underlying condition is sticky.)

**Reload action:**
- Click handler calls `loadSpecSession(state.spec.selectedPath)`.
- `loadSpecSession` re-fetches content + context, restamps `lastSeenContentHash`, clears `fileChangedDetected`, and clears the banner via its existing `setBanner("")` tail.

**Precedence in `clearTransientBanner`:**
1. If `state.spec.fileChangedDetected` and a spec is selected → re-render the file-changed banner, return.
2. Else if workspace warnings exist → re-render those (existing behavior), return.
3. Else `setBanner("")`.

```javascript
// package/minimap/ui/spec/file-change.js
//
// Pure predicate for detecting that the active spec file changed on disk
// since the last full UI load. The browser-side polling loop calls this
// every refresh tick; a `true` result means we should show the sticky
// "this file changed on disk" warning banner. DOM-free so it can be
// unit-tested under `node --test`.
//
// Watermark semantics:
// - `lastSeen` is the hash captured the last time we fully reloaded the
//   spec (initial load, apply suggestion, rollback, or click-to-reload).
//   It is "" before the first successful load.
// - `fresh` is the hash returned by the most recent getSessionContext.
// - We only fire when BOTH are non-empty and they differ. Treating a
//   missing hash as "changed" would flash a banner on every transient
//   server hiccup — too noisy for the signal we want.

export function detectSpecFileChange(lastSeen, fresh) {
  if (!lastSeen || !fresh) return false;
  return lastSeen !== fresh;
}
```

```javascript
function renderSpecFileChangedBanner() {
  // Sticky warning banner shown when the periodic poll detects that the
  // active spec file's contentHash on disk no longer matches the hash we
  // captured on the last full reload. The banner ships its own "Reload"
  // button that re-runs loadSpecSession (which restamps the hash and
  // clears the flag); the user can also dismiss the toast via the
  // standard ×, in which case the next poll re-renders it.
  if (!state.spec.fileChangedDetected || !state.spec.selectedPath) {
    return false;
  }
  statusBanner.hidden = false;
  statusBanner.dataset.tone = "warning";
  statusBanner.innerHTML = `
    <span class="status-banner-message">This file changed on disk.</span>
    <button class="status-banner-action" type="button" data-spec-action="reload-changed-file">Reload</button>
    <button class="status-banner-dismiss" type="button" aria-label="Dismiss status">&times;</button>
  `;
  return true;
}
```

**Files:**

- [ ] **Step 1: Write the test**

Create `playwright/spec-file-changed.spec.js`:

```javascript
import { test, expect } from "@playwright/test";
import fs from "node:fs/promises";
import path from "node:path";

const repoHashParam = `repo=${encodeURIComponent(process.cwd())}`;

const fixturePath = path.join(process.cwd(), "docs", "playwright-file-changed-fixture.md");
const fixturePosix = fixturePath.replaceAll("\\", "/");

const initialContent = `# File-Changed Fixture

Original line.
`;

const editedContent = `# File-Changed Fixture

Original line.

External edit appended at ${"x".repeat(8)}.
`;

test.describe("spec file-changed banner", () => {
  test.beforeAll(async () => {
    await fs.writeFile(fixturePath, initialContent, "utf8");
  });

  test.afterAll(async () => {
    await fs.unlink(fixturePath).catch(() => {});
  });

  test.beforeEach(async ({ request }) => {
    // Re-create initial content in case a previous test edited it.
    await fs.writeFile(fixturePath, initialContent, "utf8");
    const resp = await request.post("/api/spec-sessions/attach", {
      data: { file: fixturePosix },
    });
    expect(resp.ok(), `attach failed: ${resp.status()} ${await resp.text()}`).toBe(true);
  });

  test("shows banner when file changes on disk and clears it on reload", async ({ page }) => {
    const url = `/#${repoHashParam}&view=spec&file=${encodeURIComponent(fixturePosix)}`;
    await page.goto(url);

    // Wait for the spec body to render the original content.
    const body = page.locator("#spec-file-content");
    await expect(body).toContainText("Original line.", { timeout: 10_000 });

    // Banner should be hidden initially.
    const banner = page.locator("#status-banner");
    await expect(banner).toBeHidden();

    // Simulate an external edit (agent or another process).
    await fs.writeFile(fixturePath, editedContent, "utf8");

    // Within the 5 s poll cycle (+ network), the banner should appear with
    // tone="warning" and a Reload action. We give it 12 s to absorb jitter.
    await expect(banner).toBeVisible({ timeout: 12_000 });
    await expect(banner).toHaveAttribute("data-tone", "warning");
    await expect(banner.locator(".status-banner-message")).toHaveText("This file changed on disk.");
    const reloadBtn = banner.locator('[data-spec-action="reload-changed-file"]');
    await expect(reloadBtn).toBeVisible();

    // The body should still show the OLD content — we haven't reloaded yet.
    await expect(body).not.toContainText("External edit appended");

    // Click Reload — banner clears and body shows the new content.
    await reloadBtn.click();
    await expect(banner).toBeHidden({ timeout: 5_000 });
    await expect(body).toContainText("External edit appended");
  });
```
